## Objective
Make the W-0007 policy enforced by GitHub, not by a local hook, so agent merges can run without an owner click and can't be bypassed by any local process. Until this is done, every merge is owner-confirmed.

## Context
W-0008 finding: Claude Code's Bash hook can't see `gh` launched by allowed interpreters. Claude's `gh` is logged in as the owner (`etharic`, admin, `repo` scope), so GitHub can't distinguish Claude's merges from the owner's, and admin can bypass rules.

Proposed design (Claude implements its parts after the owner's setup):
1. **Owner:** create a separate identity for Claude (a machine user, or a GitHub App installed on this repository only) with write but **not** admin access, and no ruleset bypass. Re-authenticate Claude's `gh` with it (`gh auth login` by the owner; Claude never handles the token).
2. **Owner:** add a ruleset on `main`: require a PR, block force pushes and deletion (as in W-0001), and require the status check `merge-gate`. Bypass list: owner only.
3. **Claude (follow-up item):** a `merge-gate` GitHub Actions workflow that runs `scripts/merge_guard.py` policy server-side on `pull_request` and `pull_request_review` events and passes only when the PR qualifies. This is a Yellow action: one workflow, no secrets beyond `GITHUB_TOKEN`.
4. **Claude:** once 1–3 are verified, move `gh pr merge *` from ask to allow. The hook stays as early feedback.

## Acceptance criteria
- The owner chooses: implement the design above, an alternative, or keep merges owner-confirmed permanently (then cancel this item and W-0007).
- If implemented: a merge attempt by Claude's identity on a non-qualifying PR is refused by GitHub, and a qualifying one succeeds, both demonstrated on a throwaway PR in this repository.

## Verification
Owner confirms steps 1–2. Claude demonstrates step 3–4 behavior with `gh` on a test PR.
