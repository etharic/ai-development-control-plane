## Objective
Complete the migration to `etharic/ai-development-control-plane` as the canonical control plane and remove observed permission friction that would block unattended Claude operation.

## Findings
- The public repository is live and GitHub-side main/tag protections are applied (W-0001).
- `AGENTS.md` still tells GPT-5.6 to read doctrine/queue from `etharic/ai-development-lab`; other docs/config may contain the same stale canonical-repo reference.
- Repeated harmless owner prompts were caused by the blanket `Bash(gh api *)` ask rule for read-only GET requests.
- The private repo remains the historical lab/archive and contains old experiment/PR history that must remain private.

## Required work
1. Treat `etharic/ai-development-control-plane` as canonical for doctrine, queue, project registry, templates and future control-plane changes. Update every stale operational reference accordingly.
2. Preserve `etharic/ai-development-lab` only as the private historical lab/archive. Do not archive/delete it in this item; document its role.
3. Update `control/projects.json` and bootstrap/install behavior as needed so new managed projects point at the public canonical control plane.
4. Audit every current Claude Code `ask` permission against the rule: a prompt is justified only when a reasonable owner might answer No.
5. Specifically make genuinely read-only GitHub API inspection autonomous while keeping mutating `gh api` requests guarded. Do not implement this with a naive `-X` substring test: account for gh CLI semantics such as fields that can imply POST, method overrides, GraphQL, pagination/input modes, and aliases/indirect execution. Prefer an explicit safe-read wrapper/guard or narrow allow patterns that fail closed.
6. Add regression tests for representative safe GETs and mutating/ambiguous API calls. Include the exact read-only review/compare/branch queries that caused owner prompts during W-0007/W-0011.
7. Audit other ask rules and autonomize only clearly routine/read-only cases; preserve merge, release, deploy, publish, destructive Git, account/security, spend and credential boundaries.
8. Record unnecessary permission prompts as owner-attention waste in the private local telemetry mechanism.
9. Keep GitHub Actions disabled; do not implement W-0009 or the dispatcher in this item.
10. Run the full representative Windows suite and `cp.py validate`; update docs.
11. Open/update a PR in the public repo and request GPT-5.6 review. Do not merge without the currently required owner confirmation.

## Acceptance criteria
- A fresh ChatGPT `go` following public `AGENTS.md` resolves the queue/doctrine from the public repo, not the private lab.
- Read-only GitHub inspection used by routine PR/review/branch/status work no longer prompts Claude.
- Mutating/ambiguous GitHub API operations still ask/deny as appropriate.
- No weakening of protected-main, credential, destructive, production, release or spend safeguards.
- Full tests + validator pass.
