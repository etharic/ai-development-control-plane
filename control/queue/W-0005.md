## Objective
Routine development (git, gh, Python/Node/Rust tooling, installs, repo-local file work, web access) should run without permission prompts. Force pushes, pushes to protected branches, credential access, account/settings changes, releases/deploys and destructive operations stay blocked or owner-approved.

## Context
Owner request 2026-11-16, after `gh` was installed and authenticated as `etharic`. Ships inside PR #4 (W-0002) because `.claude/settings.json` is introduced there.

## Acceptance criteria
- `.claude/settings.json` has allow/ask/deny rules as documented in `docs/SECURITY.md`.
- `scripts/guard_bash.py` PreToolUse hook blocks force, delete, bulk and protected-branch pushes, including implicit ones.
- Tests cover the guard and the presence and syntax of the safeguard rules.

## Verification
`python -m unittest` (local Windows) and `python scripts/cp.py validate`.

## Result
- 2026-11-16 Claude: done on `control-plane-v2` (PR #4). 36 tests pass, validate passes. The hook was live during the session and blocked a real false positive (a quoted `git push` inside a `sed` argument), which led to quote-aware parsing. Also fixed a pre-existing isolation bug in `test_current_limits_prefers_fresher_snapshot`: it read the committed five-hour measurement. Known limit: interpreters allowed for development can read anything the user can. Branch protection (W-0001) remains the enforced boundary.
