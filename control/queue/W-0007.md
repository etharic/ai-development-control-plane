## Objective
Remove unnecessary owner merge clicks without weakening consequential-action safeguards.

The owner explicitly authorized this policy change on 2026-11-16: qualified agent merges are allowed for non-production repositories after independent agent review and required verification. Production/release/security-sensitive/destructive/account/spend actions remain owner-gated.

## Required policy
A merge may be autonomous only when ALL are true:
- target project is registered with `production: false`;
- PR targets a registered protected branch through the normal PR path (never direct push);
- PR is not draft at merge time and GitHub reports it mergeable;
- work-item acceptance criteria are satisfied;
- required representative verification has passed, with no unresolved blocking finding;
- an independent agent other than the implementation author has reviewed the PR and approved/recommended merge;
- PR contains no Red action (production deploy/release, destructive data op, spend/paid activation, credential/security/account change, irreversible deletion, or project-specific Red action);
- no project policy explicitly requires owner merge.

If any condition cannot be established, do not merge autonomously.

## Implementation requirements
- Update `docs/OPERATING_MODEL.md`, `CLAUDE.md`, security docs and tests.
- Do NOT merely move `gh pr merge *` from ask to allow. Add an executable PreToolUse guard for merge commands (or extend the existing guard cleanly) that fails closed and checks the registered project plus GitHub PR/review state through authenticated `gh`.
- Preserve the existing push guard and credential protections.
- Make merge authorization project-aware and extensible; add a project policy field if useful (for example `agent_merge` / `owner_merge_required`) and validate it.
- Tests must cover allowed non-production merge, production denial, missing independent review, draft/unmergeable PR, failed/missing verification where representable, and owner-required project policy.
- Keep allocation/resource accounting unchanged except for telemetry needed to record autonomous merges.
- After implementation, run the full Windows-local suite and `cp.py validate`.
- Update PR #4 rather than creating a duplicate.
- Because PR #4 itself is the first candidate, do not merge it until the new policy/guard has passed independent GPT-5.6 review.
