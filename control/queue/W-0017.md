## Objective
Fix the W-0016 end-to-end failure: dispatcher-launched Claude used `--permission-mode dontAsk`, which denied even routine Green commands instead of applying the repository allowlist.

## Verified Claude Code semantics
Current Claude Code documentation states:
- project `.claude/settings.json` supplies shared allow/ask/deny rules;
- `--settings` applies per-session settings above project/user files while permission lists merge;
- `permissions.denyInsteadOfPrompting: true` is supported from `--settings` and converts would-be prompts to denials; requires Claude Code >=2.1.319 (installed: 2.1.325);
- do not use `bypassPermissions`.

## Required change
1. Dispatcher subprocess must use normal/default permission evaluation so existing project Green allow rules remain effective.
2. Add per-session `--settings` JSON setting `{"permissions":{"denyInsteadOfPrompting":true}}` so Ask actions are denied instead of prompting/hanging.
3. Remove dispatcher use of `--permission-mode dontAsk`. If non-interactive `-p` requires an explicit permission mode on this installed version, use the documented normal/default mode only after verifying the CLI help/docs locally.
4. Never use bypass/dangerously-skip permissions.
5. Update docs/CLAUDE.md language from dontAsk to the actual semantics: Green allow runs; Ask becomes deny; Deny stays deny.
6. Add tests for exact spawned command/settings and a representative integration smoke:
   - routine allowed read/git/status/test command succeeds unattended;
   - an Ask-class action is denied without an interactive prompt;
   - a Deny-class action remains denied.
7. Preserve W-0015 launch state machine/dedupe/backoff/snapshot behavior.
8. Re-arm the blocked W-0016 PR key only after the fix is installed and reviewed; rerun the end-to-end verification exactly once.

## Acceptance
Dispatcher-launched Claude can perform routine allowed development work without owner prompts, while any action that would have asked the owner is denied and reported. No bypass mode. Full tests + cp.py validate pass.

## Evidence
W-0016 controlled run launched Claude successfully but outcome=blocked; its summary says every command-line call was refused beginning with `git switch main`. This proves wake/dedupe worked and permission-mode integration failed.
