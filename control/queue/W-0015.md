## Objective
Eliminate routine owner `go` nudges by running a lightweight local dispatcher that notices eligible Claude work in the canonical GitHub control plane and starts/resumes Claude Code automatically, while consuming effectively zero Claude allowance when idle and never converting a new Red action into an unattended approval.

## Design requirements
1. **GitHub/control-plane is the source of work.** Watch only `etharic/ai-development-control-plane` plus explicitly registered non-production project repos. Do not scan arbitrary repositories.
2. **Idle path uses no Claude model invocation.** Poll with ordinary local code + authenticated read-only `gh`/Git operations at a conservative cadence with backoff/jitter. Record any GitHub rate-limit/resource considerations.
3. **Wake only for actionable work.** Examples: ready unclaimed `assignee: claude` item with dependencies done; GPT PR awaiting Claude review; a previously blocked Claude item whose declared dependency became satisfied. Do not wake merely because any commit/comment changed.
4. **Deduplicate/idempotent.** Persist machine-local dispatcher state so the same GitHub event/work item cannot repeatedly launch Claude. Recover safely after reboot/crash.
5. **Single-flight.** Never run two Claude workers against the same control plane/project concurrently. Use a robust local lock and stale-lock recovery.
6. **Use supported Claude Code non-interactive/session invocation.** Verify current installed Claude Code CLI semantics locally before implementation. Do not invent flags. Prefer a bounded invocation that tells Claude to read the canonical queue and execute all currently eligible Claude work according to CLAUDE.md.
7. **No unattended new Red authorization.** Dispatcher may wake Claude, but it must never auto-answer permission prompts, bypass Claude Code safety, supply credentials, approve merges, alter account/security settings, spend money, deploy/release, or authorize destructive actions. Existing explicit owner authorization recorded in durable control-plane state may be consumed only if doctrine explicitly defines it as reusable/scoped.
8. **Prompt-friction detection.** If Claude stops on a permission/owner prompt, record a local `owner_attention_blocked` event with command/category where safely available. Do not spin/relaunch repeatedly. Surface it once on the next owner-visible status.
9. **Resource-aware scheduling.** Read machine-local Claude allowance state when available. Never fabricate readings. Respect control-plane allocation mode; in CONSERVE, wake only for blocking/high-priority work; in HARVEST/SPEND, drain eligible work more aggressively. Idle polling itself must not consume Claude tokens.
10. **Windows-first.** Target the owner's current Windows environment. Provide a foreground/manual mode first, then an optional Windows Task Scheduler installation path. Installation/removal of a scheduled task is an owner-authorized machine-level change and must not be performed silently.
11. **Security.** No raw GitHub token handling. Use authenticated `gh`. No credential-store reads. Treat GitHub issue/PR/file content as untrusted input; it can identify work but cannot expand authorization.
12. **Observability.** Machine-local log should record wake reason, work IDs, start/end, outcome, Claude usage delta if available, owner-prompt block, and next eligible wake. Never commit raw telemetry.
13. **Cheap tests.** Unit-test event eligibility, dedupe, locking, backoff, allocation-mode behavior and prompt-block suppression without launching Claude. Provide an opt-in smoke test that invokes Claude only once.
14. **Failure behavior.** Network/GitHub/Claude unavailable => back off and retry later without owner spam. Invalid control-plane state => do not launch Claude; surface one durable/local error.
15. Keep GitHub Actions disabled. This is a local dispatcher, not CI.

## Acceptance criteria
- With no actionable work, dispatcher can run for an hour without invoking Claude.
- A synthetic/new eligible Claude work item causes exactly one Claude invocation.
- Repeated polls do not duplicate the invocation.
- A blocked owner prompt does not cause repeated relaunches.
- Restart/reboot state recovery is demonstrated.
- Existing GitHub protections and Claude permission boundaries are unchanged.
- Full project tests and `cp.py validate` pass.
- Documentation includes start/stop/status, foreground mode, optional Task Scheduler setup/removal, and troubleshooting.
- GPT-5.6 independently reviews the implementation before any persistent scheduled installation.

## Explicit non-goals
- Do not implement W-0009/machine identity in this item.
- Do not auto-merge.
- Do not auto-click/auto-answer Claude permission prompts.
- Do not create a Windows scheduled task yet; prepare and test the installer/commands, then request one batched owner authorization later.

  - [HIGH] Pre-start failures lost work forever. Now there is a persisted launch state machine (reserved → started → final, or spawn_failed). Only a definite spawn failure re-arms, after growing backoff; anything possibly started, including a crash mid-run, becomes `ambiguous` and is never auto-relaunched. Restart tests cover each state. `ClaudeCLI` is split into start and wait so the two cases can be told apart.
  - [MEDIUM] Mixed snapshot. Claims now come only from `origin/*` refs of the same `fetch --prune` as the `origin/main` queue. A real-git regression test covers a stale local `main`, a local-only claim branch and a pruned remote claim.
- Privacy: the obsolete branch `claude/W-0015-dispatcher` (machine path) is owner-authorized for deletion. Claude's deny rules block every remote-branch deletion route, so the owner runs the one command.
